# FC 中国象棋 · 老头对战：设计草案

- 更新日期：2026-10-22（Asia/Shanghai）。
- 当前阶段：步骤 3 的简单 HTML 设计预览；完整规则设计及正式步骤 2 用例尚未完成。
- 状态：draft；用户已授权“先出一个简单的 HTML 原型”。当前仅做界面与操作演示，不进入正式游戏功能、Lua 或模拟器制作。
- 已确认：用户要做 FC《中国象棋》中与老头对战的版本，尽量还原原版像素画面；老头使用固定头像，不做动态表情。
- 已确认模式：只保留原版困难老头作为对手；选择界面改为“困难 / 快速模式 / 自定义模式”。自定义保留帅，其余己方初始棋子都可修改。
- 已确认操作方向（2026-10-22 更新）：采用现代点击，点己方棋子，再点目标落子；菜单、按钮与自定义棋种直接点击。此决定替代此前逐格手指操作要求，保留 FC 视觉风格。
- 已确认右下角操作区：用清楚标注“悔棋 / 认输 / 模式选择”的三个按钮替代原版功能面板；第三项返回三模式菜单，自定义从该菜单进入。
- 已确认补充：不制作暂停功能；右上信息改为当前走棋方“黑方 / 红方”及手数“001手”样式，不再放模式名、困难老头或思考状态等额外文字。
- 标记：`CONTRACT` 为已确认方向；`HYPOTHESIS` 为设计提案；`UNKNOWN` 为尚需参考或讨论的内容。下文提案不等于用户已经确认。

## 一句话定位

**回到电视机前，和那个熟悉的像素老头再下一盘中国象棋。**

- CONTRACT：核心辨识来自原版 FC 画面与困难老头的固定头像。
- CONTRACT：保留 FC 配色、棋盘构图与困难老头固定头像；用户已授权将操作改为现代点击并优化绘制清晰度。其他已确认改动包括三个模式、等待速度差异、己方初始棋种自定义及右下角三个文字按钮。
- HYPOTHESIS：优先让玩家一眼认出“就是那个版本”，并保留等待老头思考、与他较劲的情绪。
- HYPOTHESIS：面向有红白机记忆的玩家，也让会基本象棋规则的新玩家能够直接开始一局。

## 视觉方向

- CONTRACT：游戏范围仅为中间的游戏画布，包含棋盘、对局信息、固定头像、画布内按钮及菜单。外围标题/标签、装饰框、工具栏、虚拟手柄和说明不属于游戏；后续设计与平台 UI 均遵守该边界。
- CONTRACT：原型只展示游戏画布；为维持比例出现的页面留边不计入游戏美术。必需操作在画布内完成，不能依赖外围工具栏。
- CONTRACT：以原版像素画面为目标，尽量还原困难老头的固定头像。
- CONTRACT：保持 256×224 的逻辑构图比例，实际按显示尺寸与设备像素密度绘制；文字、棋子与棋线直接在高清画布生成，避免先压成低分辨率位图后放大。
- HYPOTHESIS：沿用深蓝场地、灰白棋盘、蓝/红棋字、绿色状态文字与硬边框；手形符号仅可作菜单装饰或键盘焦点提示，不再要求逐格操作。
- HYPOTHESIS：标题页、对局页、胜负反馈保持同一种低分辨率风格，不混入现代写实木纹和大幅装饰插画。
- CONTRACT：原版难度选择界面改为三个模式入口，不保留原版简易、普通及其对手；三个模式都和困难老头对战。
- HYPOTHESIS：模式选择页沿用原版像素字体、底色、头像框与光标样式，以同一个老头形象配合不同模式文案。
- CONTRACT：对局右下角采用“悔棋 / 认输 / 模式选择”三个明显的文字按钮，沿用 FC 样式；原版字母和箭头面板不按原样保留。
- UNKNOWN：标题页还原细节、字体、棋子字形和按钮样式需要进一步对照参考；模式选择页按下述已确认内容改版。

### 右下角三个按钮（已确认预留）

| 按钮 | 设计用途 | 待定细节 |
|---|---|---|
| 悔棋 | 撤回已走的棋步。 | 一次撤单步还是双方一回合、使用次数、老头思考时是否可用，尚未确定。 |
| 认输 | 玩家主动认输，结束当前对局。 | 是否二次确认、结算与返回流程，尚未确定。 |
| 模式选择 | 返回包含困难、快速、自定义的三模式菜单，自定义编辑从菜单进入。 | 当前原型先提示结束演示局，选“是”后返回；取消则保留当前局面。 |

- CONTRACT：名称直接显示用途，不沿用原版 B/H/Q/L 等难辨字母；三个入口均可用鼠标或触屏直接点击。
- HYPOTHESIS：三个按钮纵向排列在头像下方的右下操作区，用像素边框和选中标记突出当前焦点；具体尺寸、字距与棋盘/按钮之间的导航路径待静态稿确定。
- CONTRACT：右下角入口与开局的三个模式选择并存；不把“认输”解释为原版 Q 的已核实功能。

### 右上行棋信息与手数

- CONTRACT：右上两行显示当前行棋方“黑方 / 紅方”及数字手数，例如“001手”，下方保留老头固定头像。
- CONTRACT：该区域不再显示模式名称、“困难老头”或“思考中 / 红方走”等额外文字；思考过程可由画面底部状态提示说明。
- 当前原型计数口径：开局 `000手`，双方每次有效落子累计一手，玩家走后显示黑方 `001手`，电脑回棋后显示红方 `002手`；非法操作、选子和取消不增加。三位数不足时补零，超过 999 时保留完整数字。
- CONTRACT：悔棋同时恢复对应手数；标准/自定义重开及重新进入编辑均清零。上述计数口径是本项目的明确演示规则，不冒充已逐项核验的原版算法。

## 音乐与音效的平台边界

- 当前设计按千星平台提供的音乐库与音效资产选择声音；背景音乐可配置片段、音量、速度、淡入淡出和循环，短音效可由客户端 Lua 按已配置 ID 播放。
- UNKNOWN：未找到官方自定义音频上传、本地文件读取或外链播放入口的说明，不能承诺移植 FC 原版配乐与音效；后续如有新的官方能力证据再调整。
- 当前 HTML 原型没有实现音乐或音效；浏览器能力不作为千星可移植性证据。来源与核对日期见 `docs/production-plan.md` 的音频能力记录。

## 现代点击操作（已确认）

- CONTRACT：三个模式均采用“点击己方棋子选中 → 点击目标落子”。再点同一棋子取消，点另一枚己方棋子切换选择；无效走子不改变棋局。
- CONTRACT：选择状态使用清楚且稳定的边框，不靠棋子反复消失表达。悬停不自动选子，暂不做拖拽。
- CONTRACT：菜单、悔棋、认输、自定义模式、棋种选择、全部改车、确认框与重开均可直接点击。手机使用相同点击语义，不再要求虚拟十字键及 A/B 控制器。
- CONTRACT：点击位置按画面实际显示矩形映射到逻辑棋盘交点，与高清画布的内部像素数量分开；缩放后不能出现选子错位。
- CONTRACT：改变绘制分辨率或窗口尺寸只改变显示，不改变棋局、模式和已选状态。
- HYPOTHESIS：保留已有方向键/Z/X 作为辅助键盘输入，不新增独立怀旧模式开关，也不让它成为默认操作提示。
- CONTRACT：不提供画布外工具栏。再点已选棋子取消选择；模式选择使用画布内第三个按钮。离开正在进行的演示局前显示确认。
- CONTRACT：不制作暂停按钮、暂停弹层或暂停快捷键，也不在页面隐藏后要求点击继续。临时思考等待按实际经过时间推进，页面恢复可见时自动处理已到期的回棋。
- UNKNOWN：真实手机触控精度、正式 UI 最小热区及是否需要进一步放大棋盘，留待用户体验和设备验证；本轮不额外添加走法推荐等辅助。

## 模式选择（已确认）

对手统一为原版困难老头。界面保留三个入口，顺序与名称如下：

| 入口 | CONTRACT：已确认体验 | 待定细节 |
|---|---|---|
| 困难 | 和老头经典对战；老头会故意等待很久，保留原汁原味的等待体验。 | 等待时长与变化规律尚未确定，需参考原版实际节奏，不凭记忆填写秒数。 |
| 快速模式 | 仍和困难老头对战，老头思考更快。 | 具体等待时长尚未确定。 |
| 自定义模式 | 开局前修改自己的初始棋子；保留帅，其余己方棋子都能改，例如全部改成车；老头的思考等待与困难模式相同。 | 编辑交互见下方；具体等待时长与困难模式一并确定。 |

- CONTRACT：三个入口均不引入简易或普通对手。
- HYPOTHESIS：困难与快速共用同一棋力和落子策略，只改变落子等待；经典模式可以在得出落子选择后继续维持思考表现，快速模式缩短这段等待。具体棋力与原版的一致程度仍待参考核实。
- CONTRACT：困难中的长等待是刻意保留的体验，不能在后续制作中默认按“响应慢”将其优化掉。
- HYPOTHESIS：模式旁的说明可写为“经典老头 · 原味等待”“经典老头 · 快速思考”“修改己方棋子 · 自由挑战”；最终文案与版式待静态设计。

### 模式流程提案

```text
标题 → 模式选择
         ├─ 困难 ──────────→ 标准开局 → 经典长等待对战
         ├─ 快速模式 ──────→ 标准开局 → 快速思考对战
         └─ 自定义模式 → 修改己方棋子 → 开始对战
```

三个模式、核心用途及直接点击已确定；页面跳转、默认焦点与具体返回层级仍为设计提案。

## 自定义模式

### 已确认边界

- CONTRACT：玩家修改的是自己的初始棋子；老头仍是原版困难对手。
- CONTRACT：保留己方帅，其余己方初始棋子都允许修改。
- CONTRACT：支持把其余全部己方棋子改成车，不受标准开局“只有两辆车”的数量限制。以标准 16 子开局为基准，该例为 **1 帅 + 15 车**。
- CONTRACT：这是开局配置能力，不表示对局进行中可以随时变子。

### 编辑体验提案

- HYPOTHESIS：进入后显示完整开局棋盘；只突出可编辑的己方棋子，帅显示保留标记，对方棋子作为参照。
- CONTRACT：点击己方非帅棋子，再点击“车 / 马 / 炮 / 相 / 仕 / 兵”中的目标棋种完成替换；帅保持锁定，不提供增加第二个帅的选项。
- HYPOTHESIS：只替换棋种，保留棋子所属方、原始位置和己方总数；移动位置、增删棋子或修改老头阵容暂不纳入设计。
- HYPOTHESIS：提供“全部改车”“恢复初始”“开始对局”“返回”操作；“全部改车”保留帅。
- HYPOTHESIS：新棋种从所在格按该棋种的走法行动，不自动移回其标准出生位置。例如底线原本的马改成车后，按车的走法行动。
- HYPOTHESIS：若选相、仕等有区域限制的棋种，其行动范围仍遵循相应规则；非标准出生格的具体合法性限制需在后续规则设计中明确，避免玩家生成无法理解的配置。
- CONTRACT：自定义对战采用与困难模式相同的思考等待，不使用快速模式的短等待；两者以后调整等待时长时应保持一致。
- UNKNOWN：再次进入、重开或退出后是否保留上次配置，及非标准配置的具体胜负、和棋边界，后续设计再定。

## 老头固定头像（已确认）

- CONTRACT：三个模式使用同一个困难老头固定头像，尽量还原原版脸型、秃顶、眼镜和胡须的像素特征。
- CONTRACT：思考、吃子、受将、获胜或落败时均保持同一头像；不制作动态表情、头像动作或表情分镜。
- HYPOTHESIS：思考、将军和胜负等状态通过文字与棋盘反馈呈现，具体形式随页面设计细化。

## 一局体验提案

`进入游戏 → 点击选择模式 → 自定义时点击修改己方初始棋子 → 开始对战 → 点棋子、点目标落子 → 老头思考并回棋 → 局势反馈 → 胜负结算 → 再来一局`

- HYPOTHESIS：首个可玩的版本以玩家执红、老头执黑的一局人机对弈为中心。
- CONTRACT：采用鼠标/触屏直接“点棋子、点目标”的操作，稳定显示选中状态。
- CONTRACT：困难和自定义保留相同的长思考等待，仅快速模式缩短等待；具体正式时长仍待设计。
- HYPOTHESIS：选中、非法走子、吃子、将军和胜负的反馈优先对照原版，不额外加入现代辅助提示；老头头像保持固定。
- UNKNOWN：是否还原原版倒计时与关卡递进；悔棋入口已经确定，其限制和具体撤回规则待定。暂不把 180 秒或其他数值锁为要求；模式范围已经按上述三个入口确定。

## 规则设计关注点

- HYPOTHESIS：采用标准中国象棋走法，特别关注蹩马腿、塞象眼、炮架、九宫与过河限制、自将和将帅照面；自定义修改初始棋种，不默认放宽各棋种的行动规则。
- HYPOTHESIS：终局应清楚区分将死、困毙、认输、超时与和棋；具体纳入哪些终局方式、采用什么重复局面规则，需在范围确定后写成规则契约。
- UNKNOWN：原版困难棋力、开局习惯与实际等待节奏需要参考核实；不能仅靠增加等待时间声称完整复现了原版 AI。
- UNKNOWN：千星上头像表现、输入、棋盘热区与 AI 运算的适配成本。这里只登记设计风险，当前不做实现或性能承诺。
