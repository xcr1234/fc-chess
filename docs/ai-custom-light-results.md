# 自定义娱乐 AI 调整结果

日期：2026-10-24。依据用户“自定义是娱乐模式，不需要复杂计算”的新要求，保留 JS 1.0 新内核，单独缩减自定义搜索。困难/快速配置、实际吃将规则、自由士相、开局库隔离、附加等待和 UI 均保留。

## 现在的行为

- 自定义默认最多搜索2层，2000节点保护，1.5秒逻辑截止；仍按每步128操作/32新节点及约3ms的协作式墙钟保护分帧。
- 取消自定义的静态吃子延伸和将军延伸，默认关闭TT。到达浅层边界后采用静态估计，避免15车的战术分支持续占据首轮。
- 真实将帅被吃、当前直接吃敌将仍优先处理；根着法若允许对方立即吃己将，仍会得到失将评价。能够选择自由士相攻击下的安全应对和吃掉无保护重子。
- 浅层估计不保证解决连续将军、复杂兑子或长杀棋；不将这类估计写为完整战术搜索的精确缓存。TT另区分静态/静态搜索叶子策略，离线完整搜索可以独立验证。

1.5秒是搜索的逻辑截止上限；算完两层可以提前结束。已有附加等待另行计算，这不是总可见等待时间，也不等于设备CPU时长。

## 执行结果

| 检查 | 结果 |
|---|---|
| 新定向用例 | 修改前3/9，15车首轮、轻量配置等新要求未满足；修改后9/9 |
| 宿主采样 | 8局面 × 30/60 FPS × 2次，共32次；均完成至少一轮，完整深度1–2，首轮保底0次 |
| 同一15车出库起点 | 旧策略在4/8秒逻辑预算仍为0层；本策略1.5秒上限下，30 FPS两次为1层、60 FPS两次为2层 |
| 真实自对弈 | 15车11、自由士相44、标准外观自定义31半回合，共86；均实际吃将结束，无非法着、状态恢复失败、重复或首轮保底 |
| 原规则与核心回归 | 11/11套件，117条Lua PASS组，另含2次用户原局回放及固定JS核心对照 |
| 模拟器 | 67/67用例，264条断言；15车额外检查轻量策略与首轮完成 |
| 基准驱动与构建工具 | 28/28 |

采样起点为此前15车棋谱的6个黑方回合，以及自由士相、标准外观自定义各1个出库局面；不是广泛或独立棋力集。原15车起点本轮实际宿主计算约103–134ms；通过改变视野和停止条件换取可完成的比较，不将该差异当作同棋力吞吐提升比例。

持续对局最长宿主step：15车约4.13ms、自由士相约8.77ms、标准外观自定义约6.98ms。仍有超过8ms的宿主峰值，不据此宣布硬实时或真机性能达标。无真机、部署或新增视觉证据。
