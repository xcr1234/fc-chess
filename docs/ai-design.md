# Lua 象棋 AI 与老头等待设计

- 日期：2026-10-22（Asia/Shanghai）；状态：算法结构已纳入设计；参数为可调初值；正式Lua未实现、未进行性能测试。
- CONTRACT：三个模式同一棋力；快速算完即走，困难/自定义计算完成后按当前局面复杂度附加等待。
- 算法选型是工程建议，不代表已经复现 FC 原版引擎或达到某个搜索深度。

## 推荐架构

建议使用 **Negamax Alpha-beta + 迭代加深 + 走法排序 + 受控静态搜索 + 有限置换表 + 小型开局库**。

Alpha-beta 减少无须继续展开的分支，效果依赖走法排序；迭代加深保证预算到期时有上一轮完整结果。开局库用于原始阵容开局节省计算，出库后仍依赖正常搜索，不能代替中残局引擎。

黑方一手流程：

`检查终局 → 有效基本着法 → 可用开局库 → 未命中则迭代加深搜索 → 着法与复杂度摘要 → 快速直接提交 / 困难与自定义动态等待 → 版本与合法性复核 → 提交`

参考依据：作者的 [ElephantEye 搜索源码](https://github.com/xqbase/eleeye/blob/master/eleeye/search.cpp)包含 Alpha-beta 系列搜索、静态搜索及迭代控制；[开局库源码](https://github.com/xqbase/eleeye/blob/master/eleeye/book.cpp)按局面查找着法。这能支持算法选择，不能推断千星 Lua 的速度。较轻的 [XQWLight](https://github.com/xqbase/xqwlight)可作结构参考，本次未复制其代码或书库。

## 第一版搜索功能

| 项目 | 设计 | 目的 |
|---|---|---|
| Negamax Alpha-beta | 统一搜索框架，先正确实现上下界 | 避免无意义分支继续展开 |
| 迭代加深 | 完成1层、2层……，预算到期取最近完整迭代 | 不写死必须完成的深度 |
| 着法排序 | 上轮主变化/置换表着法优先，再有利吃子、杀手着法与历史启发 | 提高早截断的机会 |
| 静态搜索 | 叶子分析必要吃子，吃将优先；不强制应将 | 减少刚吃子就被回吃的短视 |
| 置换表 | 有容量上限，记录签名、深度、上下界类型、分数、最佳着法、代次 | 避免重复计算，限制内存 |
| 简明评估 | 子力、位置、机动性、将帅被吃风险，逐项验证与增量维护 | 以可测成本建立基本棋力 |
| 小型开局库 | 精简标准局面、候选着法与权重 | 节省开局计算，避免永远同一线路 |

静态搜索计入总预算，设置最大总层数和节点上限以保证结束。仅按基本走法展开，不做自将过滤、强制应将、将死或循环判和；真正吃将返回终局高分。硬预算到期传播中止，不把未完成分数写成精确值。

第一版先不加入空步裁剪、激进减深和复杂重搜；以战术棋谱及性能数据建立基线后逐项增加。自定义极端子力下，标准引擎的经验性剪枝条件需要重新验证。

## Lua 计算与内存控制

- 紧凑棋盘试走/撤销，每层只记录变化；避免每节点深复制棋盘、生成嵌套对象或拼接完整棋谱。
- 各深度复用着法缓冲，增量维护子力/位置分和局面键；避免每节点反复完整扫描所有攻击关系。
- 哈希区分棋子分布、行棋方和规则档案。置换表仅为性能缓存，不把命中次数当作循环/长将裁判，也不因搜索路径重复而给实际棋局判和。
- 置换表区分 exact/lower/upper；命中着法再次校验；中断节点不写精确值；吃将终局分按搜索层数校准。
- 开局库不默认依赖平台本地文件、网络或原生模块。优先以精简 Lua 数据模块随单文件打包交付，具体读法须核对官方能力。
- 分帧推进，搜索可中断，按钮与画面持续响应；不能假定平台可用线程、Worker或任意协程。具体调度方式须取得官方资料后实现。
- 三个模式采用同一节点/深度预算和保底策略；另设一致的总耗时保护上限。快速不缩减预算。
- 没有真机吞吐数据，不承诺固定层数/毫秒；总节点、每帧工作量、置换表容量留待步骤5–7校准。

预算耗尽返回最近完整迭代。第一层也未完成时返回预先验证的合法保底着法，并记诊断；没有基本走法则按详细设计跳过该方，不能误报将死或AI卡住。所有中止路径均须完整撤销试走。吃将分应显著高于非终局评价；15车局子力总分也不能超过它。

## 开局库与自定义

书库按“完整局面 + 行棋方 + casual-capture-v1”索引，不能按第几手或只看固定着法序列。候选必须通过合法性验证；没有可用候选则搜索，玩家偏离书路不报错。书着需按本项目允许送将的娱乐规则重新验收；不能直接调用会强制应将的普通引擎替代此规则。困难/快速书库和选择策略相同；加权选择使用可注入seed供回归。

自定义红方士相活动范围已变化，首版**全部自定义局面禁用普通开局库**，即使外观仍是标准开局。以后只有专门验证过该规则档案的书库才能启用。置换表也按规则档案隔离。

不使用假定“一方最多两车、两马、两相”的固定棋子表；1帅15车为必测压力局。红方士出宫、相过河必须进入AI生成、威胁判断与评估，不只在玩家点击层放行。

## 三种模式同一棋力

相同局面、规则档案、历史、seed、预算和初始缓存条件下，困难/快速得到相同着法。自定义共用搜索与评估实现，但阵容/规则不同，不要求选择相同着法。

模式差异只发生在计算结束后。困难/自定义等待期间不继续加深，快速不提前取较浅结果。不会因慢模式多等几秒而实际多搜几秒。

## 根据局面复杂度动态等待

复杂度针对老头当前要作答的局面，在计算完成后生成一次摘要。复用搜索产出的信息，不额外再搜一遍，也不以设备运行耗时充当复杂度。

| 因素 | 来源 | 作用 |
|---|---|---|
| B 可选走法 | 根局面有效基本着法数，饱和归一化 | 多选项倾向更长；仅一步按简单处理 |
| T 战术性 | 根局面吃子/直接威胁将帅候选及已搜索变化 | 战术分支多倾向更长；将帅受攻击不直接等于复杂 |
| A 候选接近度 | 同一完整迭代下最佳与次佳的可比较分差 | 差距小更难取舍，差距大更短 |
| U 选择不稳定度 | 连续完整迭代的最佳着法是否变化 | 多次变化小幅延长，不使用半轮结果 |

HYPOTHESIS：建议初值 `C=0.35B+0.25T+0.30A+0.10U`，各项为0..1；`W=round(4+12C)`秒，初始范围4..16秒。仅一步有效基本着法时C=0。用户确认的是动态原则，尚未确认这组上下限或权重。

为使提案可复算，初始归一化定义如下；这些值均须试玩调参：

- `B=clamp((N-1)/59,0,1)`，N为有效基本着法数。
- `T=clamp(F/max(N,1),0,1)`，F为产生吃子或直接威胁将帅的根着法数，一着同时满足只计一次；将帅受攻击时不把全部可选着法自动计为战术。
- `A=1-clamp(gap/150,0,1)`，gap是同深度可比较的最佳/次佳分差，150采用兵基础价值100的评分单位。
- U为最近最多3对相邻完整迭代中最佳着法变化的比例；不足2次完整迭代则缺项。

A只能使用两个同深度精确根分数。Alpha-beta截断产生的上下界不是精确次佳值；缺项对其余权重重新归一化，不为延时指标强行重搜。只有一步有效基本着法的短路优先于其他因素。

开局库命中时通常仅B/T可得，按剩余项计算；都不可得则用简单档。15车等大分支局面在C=1处饱和，不能无限等待。困难/自定义同一模型，快速固定W=0，不加入无依据随机抖动。

本步可见用时=实际计算时间+W+确认层导致的提交延后。W从计算完成时开始，等待中不继续搜索、不每帧重新生成或延后截止点。用户只看到原有思考提示及步时，不新增复杂度/深度/分数仪表。

## 校准与验收

| 样本 | 验证目标 |
|---|---|
| 标准开局、命中/出库 | 书着合法，出库正常，困难/快速同条件同着法 |
| 唯一基本走法 | 找到唯一合法步，复杂度为简单档 |
| 回吃与将帅受攻击叶子 | 静态搜索不把亏子当获利，仍允许不应将的基本着法 |
| 多候选接近中局 | 根分差可靠，等待高于明显简单局面 |
| 15车/跨河相/出宫士 | 无固定数量假设、规则档案正确、标准书库禁用 |
| 搜索/等待中悔棋与离局 | 工作棋盘撤销、旧结果不污染新局 |
| 真机性能 | 每秒节点量、完整深度、计算总时长、最长帧工作时间、内存趋势与按钮响应 |

性能记录区分实际计算、附加等待和黑方步时；诊断不新增玩家局时功能。模拟器数据不作为真机性能结论。
