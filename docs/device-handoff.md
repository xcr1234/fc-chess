## 导入、索引和挂载

1. 导入`fc-chess-client.gia`，在客户端控件模板库确认下表四个模板是独立顶层模板。
2. 导入`fc-chess-server.gia`，把其中的“客户端控件容器”放到实际游戏使用的界面布局。保持初始激活、可见；其内部应有容器节点`FCChessHost`。
3. 核对四个客户端模板的实际索引。若与下表不同，先回传“模板名 = 新索引”；由AI同步源模块、完整存档及新产物，再继续试玩。不要拿运行时控件ID代替模板索引。
4. 用户本轮选择手动导入。在“客户端脚本资源管理器”新建脚本映射，关联本次[export/main.lua](../export/main.lua)，或关联用户手动放入游戏脚本目录的同一份文件；项目不配置部署目标、不执行复制。不要关联测试脚本或开发模块。
5. 在`FCChessHost`的“脚本”页添加此入口映射，挂载一次。四个基础模板不挂游戏入口；否则每次动态实例化都会重复启动游戏。
6. 保存关卡并重新试玩，在日志中勾选“客户端脚本”。应出现编译日期、Initialization started/completed与`[fc-chess][ready] UI ready test=false`，主屏显示困难/快速/自定义三模式。

## 第一轮真机试玩

每次先记录设备、分辨率/横竖屏、是否触屏、当前产物日志时间。仅以下实际做过的项目才记通过。

| 操作 | 预期与回传重点 |
|---|---|
| 进入菜单→快速→最左/最右路兵前进 | 棋盘/头像/字形完整，边缘热区正确，快速模式无附加等待，回棋后002手 |
| 选兵并尝试后退 | 不移动、不增加手数，显示不能走 |
| 悔棋→另走一步 | 回000手/红方，旧回棋不再出现 |
| 困难落子→思考中点认输→否 | 按钮能响应，步时继续，取消后最多提交一次回棋 |
| 再次认输→是→再来一局，重复一次 | 结果/重开正常，新局000手，双方步时重置 |
| 模式选择→自定义→全部改车→开始 | 1帅15车；搜索时测试悔棋、认输和模式选择是否卡顿 |
| 自定义选择士/相并走出标准区域 | 红方自由士相按当前娱乐规则可走；相眼仍生效 |
| 吃掉将/帅的局面 | 实际吃将才结束；允许送将/不应将，不提前判将死或循环 |
| 思考中切后台再恢复 | 记录切换前后步时、实际间隔和回棋次数；后台补时尚未承诺 |
| 手机横屏/实际设备尺寸 | 画布完整，文字/弹层不裁切；头像无越界，触点准确 |

重点观察菜单三份300椭圆头像的首次创建成本、15车搜索长帧和确认/悔棋响应。第6步宿主长局最大单次搜索推进约437ms，不能把宿主数值当作真机帧耗时或视为已消除卡顿。

有异常时回传：设备、操作顺序、期望/实际、是否每次发生，以及相关客户端脚本日志。黑屏优先核对外层容器激活/可见、四个模板真实索引、入口映射路径及FCChessHost挂载；初始化完成后才讨论棋规问题。正常日志无法报告的加载卡住，可检查脚本目录中的`ErrorLog.txt`（官方说明仅在特定异常时创建）。
