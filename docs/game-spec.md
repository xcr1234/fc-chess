# FC 中国象棋详细设计 v0.2

- 日期：2026-10-22（Asia/Shanghai）；范围/确认状态以 [GDD](gdd.md) 为准，算法见 [AI方案](ai-design.md)。
- 本文是设计，尚无正式游戏运行证据；HYPOTHESIS为待调参/决策提案，不默认已获用户确认。

## 棋盘和规则档案

棋盘索引file=0..8（左至右）、rank=0..9（黑方底线至红方底线）；不是UI坐标。红方向rank减小前进，黑方相反。

标准布局：黑底线车马象士将士象马车，炮(1,2)/(7,2)，卒(0/2/4/6/8,3)；红方镜像，炮rank7、兵rank6。红帅(4,9)、黑将(4,0)，双方各16子，红先。

| 棋种 | 基本走法/阻挡 | 标准活动范围 | 自定义红方差异 |
|---|---|---|---|
| 车 | 直线，路径无子 | 全棋盘 | 无 |
| 马 | 一直一斜；先直行的一格有子即蹩腿 | 全棋盘 | 无 |
| 炮 | 空走直线无阻；吃子时起终点间恰有一个炮架，任一方子均可作架 | 全棋盘 | 无 |
| 士/仕 | 斜一格 | 本方九宫 | 不限九宫，全棋盘 |
| 象/相 | 斜两格，象眼为空 | 本方半场 | 可过河，不限传统落点 |
| 将/帅 | 横竖一格 | file3..5；黑rank0..2，红rank7..9 | 无，仍限九宫 |
| 卒/兵 | 前一格，过河后另可横一格，不可后退/升变 | 红rank≤4、黑rank≥5为已过河 | 按当前格判定，不保留原棋种能力 |

所有模式只禁止吃己方子、越界、原地落子与违反棋种基本走法。允许不应将、送将以及将帅照面；不计算自将、不强制保护己方将帅，不提前判将死/困毙。能吃将时仍可改走其他子，双方照常轮流行动。同列无遮挡时将/帅可飞将吃对方将帅，其他将帅移动仍限本方九宫。

规则档案：困难/快速为`casual-capture-v1`，自定义为`custom-capture-free-advisor-elephant-v1`；自定义未改棋种也使用自定义档案。玩家校验、AI走法和评估共用档案。红方自由士相进入AI威胁判断，黑方仍按基本区域限制。

[WXF基础介绍](https://www.wxf-xiangqi.org/images/xiangqi-intro/xiangqi-introduction-for-wxf.pdf)只作棋种基本走法参考；本项目吃将、送将、自由士相规则属于娱乐变体，不采用赛事裁判。

## 选子、提交与结束

1. 红方回合点己方子选中；再点同子取消，点其他己方子切换。未选子时点空点/黑子只提示选择己方子。
2. 选中后点目标尝试落子。违反基本走法时保持局面、选择和手数，本步计时继续。
3. 有效提交一次性记录悔棋快照、移动/吃子、停本方步时、手数加一；不因该步使自己受攻击而拒绝。
4. 目标是黑将则玩家立即获胜；目标是红帅则玩家立即落败。保留吃将后的棋盘，显示原因，停止步时/任务，不启动下一回合。可以直接吃将，不要求先出现将军提示。
5. 没有吃将才切换行棋方、清零新行棋方步时。将帅受到攻击只作为AI评估/复杂度特征，不产生强制应将或结果层。
6. 棋局正常开始时必须有双方将帅；结束后被吃的一方可缺将。坏初始化数据缺将属于加载错误，不能自动记作胜利。
7. 主动认输确认后判玩家负；回菜单不计认输。没有时间判负、下一关或主动求和入口。

### 循环与长将：明确不做

同一局面重复任意次数仍继续；连续攻击将帅也不触发警告、罚分、强制变招、和棋或判负。不建立用于裁判的重复局面历史，不做长捉、不动兵/吃子手数和裸将判和。悔棋历史仅用于恢复局面。搜索置换表是性能缓存，不得转化为循环裁判。

### 极端无走法的兜底（DESIGN）

无基本走法的一方自动跳过本次行动，不按困毙判负，不增加手数；对方新一步清零计时。双方都无基本走法时停止步时，显示“本局无法继续／双方暂无可走棋”，提供重开/菜单，不记胜负或和棋。这只检查走法生成列表是否为空，不做将死搜索。

## 状态与确认层

| 状态 | 输入 | 转移 |
|---|---|---|
| mode-select | 三模式 | 标准开局或自定义编辑 |
| custom-edit | 非帅红子、六棋种、全部改车/恢复初始/开始/返回 | 开始时复制草稿为本局初始阵容 |
| player-turn | 选子/落子、悔棋/认输/模式选择 | 红有效提交后AI计算，吃将则终局 |
| ai-search | 悔棋/认输/模式选择 | 计算完成：快速提交，其他进入等待 |
| ai-wait | 悔棋/认输/模式选择 | 到期复核并提交已选着法，不继续搜索 |
| result | 再来一局/模式选择 | 保留本局初始阵容重开，或回菜单 |

确认层/棋种层阻断输入穿透，一次指针动作不能在切页后再触发下一页。确认默认否，取消键等同否。

确认层不是暂停：步时和AI任务继续。黑方准备完成且等待到期时，暂存回棋，避免确认背景变化；点否后就绪结果提交一次，未就绪则继续原计算/剩余等待。点是离局时先取消任务、等待和挂起结果，再结算/回菜单。

## 编辑与重开

六棋种为车、马、炮、相、仕、兵；相同棋种替换无变化。帅/黑子不可编辑，只改棋种、不改位置/阵营/数量。全部改车得到1帅15车，恢复初始得到标准红方阵容但仍属自定义规则。

自定义草稿本次会话内保留；开始时另存一份本局初始阵容，后续草稿不覆盖它。再来一局取本局初始阵容与模式，重置棋盘、历史、步时、手数、选择和AI任务。无跨次游玩保存、阵容分享、随机暗子或下一关。

## 步时与手数

只记录一步耗时，不记录或显示局时。

| 事件 | 时间栏行为 |
|---|---|
| 开局 | 红方00:00起表，黑方00:00 |
| 红落子 | 红方停住本手用时，黑方00:00起表 |
| 黑计算完成 | 黑方继续计时，包含附加等待 |
| 黑落子 | 黑方停住本手用时，红方新一步清零起表 |
| 非行棋方 | 保留该方上一手步时；没有上一手则00:00 |
| 选子/非法/取消/确认层 | 当前行棋方继续计时，不清零、不暂停 |
| 悔棋 | 红方新一步00:00起表，黑方恢复被撤回回合前的上一手步时 |
| 终局 | 双方停住，不启动下一步 |
| 重开 | 双方显示清零，红方开始新一步 |

显示mm:ss，秒向下取整，内部保留亚秒；59.9秒显示00:59，60秒显示01:00，满100分钟显示100:00，不回绕或判负。

黑方步时=计算耗时+附加等待+确认层导致的提交延后。快速W=0，实际计算仍计入步时。计时的诊断数据不得累计成玩家局时功能。

无暂停，前台按实际经过时间推进。后台补时须核验平台时钟/生命周期，不假定dt已包含后台间隔；离开整个游戏后不承诺持续运行或恢复。

手数为已提交着法总数，开局000，至少三位，超过999完整显示。非法/选子/确认不增加；悔棋恢复；终局保留最终手数。步时不影响手数或胜负。

## 悔棋和过期任务

一次撤回上次玩家行动：红走黑未走时撤一步，双方走完撤两步。次数不限，可继续撤至初局；没有可撤步则提示尚无棋步可悔。结果页不开放悔棋。

恢复玩家落子前的棋盘、手数与上次步时显示数据，清空选择/临时提示，新红方步时清零。计算/等待均可取消，不恢复成累计时间。

每次开局、悔棋、认输、回菜单递增局面版本。计算与等待绑定版本、规则档案、行棋方；提交前复核，过期即丢弃。搜索使用私有工作棋盘，试走不进入可见局面、手数或步时历史。

## 动态等待接口

计算输出合法着法、完整深度、根候选数、战术摘要和可用分差；表现层计算一次W并锁定截止点。困难/自定义同一策略，快速W=0；等待期间不额外搜索。

候选分差只能使用同一完整深度的可比较精确值，截断上下界不能冒充次佳分。书库命中时用已有特征降级计算复杂度，不为制造等待再做完整搜索。公式、归一化与试验初值见[AI方案](ai-design.md)。

3. 重新取得平台输入、控件、生命周期和计时API正文，确认分帧与后台能力。本轮HTTP读取失败，不凭旧记录编造新接口。
4. 正式用例与运行画布/夹具约定见[测试说明](../tests/README.md)，已作离线格式校验；步骤5落实夹具及控件后才执行有效Red→Green→Regress。
5. 用标准局、复杂中局、唯一基本走法、15车与自由士相局校准搜索预算和等待参数。
