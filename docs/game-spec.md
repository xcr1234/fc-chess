# FC 中国象棋详细设计 v0.3

- 日期：2026-10-23（Asia/Shanghai）；范围/确认状态以 [GDD](gdd.md) 为准，算法见 [AI方案](ai-design.md)。
- 本文为当前设计契约；正式Lua与模拟器运行证据见production-plan及records/playtest；HYPOTHESIS为待调参/决策提案，不默认已获用户确认。

## 棋盘和规则档案

棋盘索引file=0..8（左至右）、rank=0..9（黑方底线至红方底线）；不是UI坐标。红方向rank减小前进，黑方相反。

标准布局：黑底线车马象士将士象马车，炮(1,2)/(7,2)，卒(0/2/4/6/8,3)；红方镜像，炮rank7、兵rank6。红帅(4,9)、黑将(4,0)，双方各16子，红先。

| 棋种 | 基本走法/阻挡 | 标准活动范围 | 自定义红方差异 |
|---|---|---|---|
| 车 | 直线，路径无子 | 全棋盘 | 无 |
| 马 | 一直一斜；先直行的一格有子即蹩腿 | 全棋盘 | 无 |
| 炮 | 空走直线无阻；吃子时起终点间恰有一个炮架，任一方子均可作架 | 全棋盘 | 无 |
| 士/仕 | 斜一格 | 本方九宫 | 不限九宫，全棋盘 |
| 象/相 | 斜两格，象眼为空 | 本方半场 | 可过河，不限传统落点 |
| 将/帅 | 横竖一格 | file3..5；黑rank0..2，红rank7..9 | 无，仍限九宫 |
| 卒/兵 | 前一格，过河后另可横一格，不可后退/升变 | 红rank≤4、黑rank≥5为已过河 | 按当前格判定，不保留原棋种能力 |

所有模式只禁止吃己方子、越界、原地落子与违反棋种基本走法。允许不应将、送将以及将帅照面；不计算自将、不强制保护己方将帅，不提前判将死/困毙。能吃将时仍可改走其他子，双方照常轮流行动。同列无遮挡时将/帅可飞将吃对方将帅，其他将帅移动仍限本方九宫。

规则档案：困难/快速为`casual-capture-v1`，自定义为`custom-capture-free-advisor-elephant-v1`；自定义未改棋种也使用自定义档案。玩家校验、AI走法和评估共用档案。红方自由士相进入AI威胁判断，黑方仍按基本区域限制。

[WXF基础介绍](https://www.wxf-xiangqi.org/images/xiangqi-intro/xiangqi-introduction-for-wxf.pdf)只作棋种基本走法参考；本项目吃将、送将、自由士相规则属于娱乐变体，不采用赛事裁判。

## 选子、提交与结束

1. 红方回合点己方子选中；再点同子取消，点其他己方子切换。未选子时点空点/黑子只提示选择己方子。
2. 选中后点目标尝试落子。违反基本走法时保持局面、选择和手数，本步计时继续。
3. 有效提交一次性记录悔棋快照、移动/吃子、停止红方步时或定格AI数字、手数加一；不因该步使自己受攻击而拒绝。
4. 目标是黑将则玩家立即获胜；目标是红帅则玩家立即落败。保留吃将后的棋盘，显示原因，停止步时/任务，不启动下一回合。可以直接吃将，不要求先出现将军提示。
5. 没有吃将才切换行棋方、重置新行棋方的步时或模拟数字。将帅受到攻击只作为AI评估/复杂度特征，不产生强制应将或结果层。
6. 棋局正常开始时必须有双方将帅；结束后被吃的一方可缺将。坏初始化数据缺将属于加载错误，不能自动记作胜利。
7. 主动认输确认后判玩家负；回菜单不计认输。没有时间判负、下一关或主动求和入口。

### 循环与长将：明确不做

同一局面重复任意次数仍继续；连续攻击将帅也不触发警告、罚分、强制变招、和棋或判负。不建立用于裁判的重复局面历史，不做长捉、不动兵/吃子手数和裸将判和。悔棋历史仅用于恢复局面。搜索置换表是性能缓存，不得转化为循环裁判。

### 极端无走法的兜底（DESIGN）

无基本走法的一方自动跳过本次行动，不按困毙判负，不增加手数；对方新一步清零计时。双方都无基本走法时停止步时，显示“本局无法继续／双方暂无可走棋”，提供重开/菜单，不记胜负或和棋。这只检查走法生成列表是否为空，不做将死搜索。

## 状态与确认层

| 状态 | 输入 | 转移 |
|---|---|---|
| mode-select | 三模式 | 标准开局或自定义编辑 |
| custom-edit | 非帅红子、六棋种、全部改车/恢复初始/开始/返回 | 开始时复制草稿为本局初始阵容 |
| player-turn | 选子/落子、悔棋/认输/返回标题界面 | 红有效提交后AI计算，吃将则终局 |
| ai-search | 悔棋/认输/返回标题界面 | 计算完成：快速提交，其他进入等待 |
| ai-wait | 悔棋/认输/返回标题界面 | 到期复核并提交已选着法，不继续搜索 |
| result | 再来一局/返回标题界面/返回棋盘 | 保留本局初始阵容重开、回菜单，或进入终局查看 |
| result-review | 悔棋/返回标题界面 | 保留终局，棋子/AI/计时冻结；悔棋确认后恢复player-turn，退出仍需确认 |

确认层/棋种层阻断输入穿透，一次指针动作不能在切页后再触发下一页。确认默认否，取消键等同否。

获胜/失败结算追加“返回棋盤”，原再来一局保留，离局按钮统一标为“返回标题界面”。返回后显示最终棋盘与“本局已結束，悔棋後可繼續”，不重新计算AI，不启动步时，不能选子或提交走棋。悔棋的是/否流程保持：是恢复到上一手玩家落子前，红吃将撤一手、黑吃将撤红黑一对，恢复被吃将帅、手数与上一轮AI边框/数字，红方步时重新开始；否仍冻结。认输局也可查看/悔棋，无历史则提示且不解锁。查看时认输按钮置灰无动作；返回标题界面仍确认。查看/悔棋均不重播音效；重开或悔棋清除旧胜负文案。

对局及结果页离局按钮显示“返回標題界面”，ModeButton动作标识不变。对局离局确认标题“返回標題界面？”，下方以8号小字显示“返回後無法恢復當前對局”；取消保留原局，确认回标题页。

确认层不是暂停：红方步时、AI数字和任务继续。黑方准备完成且等待到期时，暂存回棋，避免确认背景变化；点否后就绪结果提交一次，未就绪则继续原计算/剩余等待。点是离局时先取消任务、等待和挂起结果，再结算/回菜单。

## 编辑与重开

六棋种为车、马、炮、相、仕、兵；相同棋种替换无变化。帅/黑子不可编辑，只改棋种、不改位置/阵营/数量。全部改车得到1帅15车，恢复初始得到标准红方阵容但仍属自定义规则。

自定义草稿本次会话内保留；开始时另存一份本局初始阵容，后续草稿不覆盖它。再来一局取本局初始阵容与模式，重置棋盘、历史、红方步时、AI数字、落子边框、手数、选择和AI任务。无跨次游玩保存、阵容分享、随机暗子或下一关。

2026-10-24用户将自定义明确为娱乐模式：使用同一JS 1.0新内核的浅层策略，默认最多2层、无静态/将军延伸、1.5秒逻辑截止及2000节点保护，不承担困难/快速的棋力目标。仍优先检查实际吃将与对手下一手吃将；到达视野边界后使用静态估计，不继续复杂应对树。标准外观的自定义阵容也使用此策略并禁库。附加等待规则保持下文约定，1.5秒不是总可见等待时间或真机CPU耗时。

## 红方步时、AI数字与手数（2026-10-23更新）

红方仍仅记录本手耗时，mm:ss向下取整、允许100:00，不判超时负；新红方回合清零，落子停表。AI下方替换为五位模拟思考数字，不再显示步时或局时。

| 事件 | 左栏行为 |
|---|---|
| 开局 | 红方00:00起表，AI显示00000 |
| 红落子 | 红方停住，AI从00000开始增长 |
| AI计算/附加等待/确认延后 | 数字按同一回合经过时间增长，每秒最多刷新20次；确认不暂停 |
| AI实际落子 | 数字定格，红方新一步清零起表 |
| 悔棋 | 红方00:00，恢复对应历史局面的AI数字与落子边框 |
| 终局/离局 | 数字与步时停止；开新局或进入菜单/编辑清空AI反馈 |

DESIGN：t为本回合AI实际经过秒数，L(t)=min(40000,1000+floor(1800t))。增长阶段t按0.05秒采样，显示floor(L(t)×(1-exp(-6t)))；落子定格L(t)，至少01000。等待1/4/8/16秒对应最终02800/08200/15400/29800，约21.67秒封顶40000。即时书库回棋直接显示01000。增长算法只管表现，不改搜索预算、棋力或附加等待，也不调用共享随机源。

本回合时间包含AI计算、附加等待及确认层导致的实际提交延后。后台仅消费平台实际提供的dt，不承诺系统后台补时。红方回合不会推进AI数字。

AI提交有效着法后以两个青色边框标出起点和落点，落点边框加粗；黄色玩家选框独立保留。标记保持至下一次AI有效回棋，玩家选子/非法操作不覆盖；悔棋恢复对应历史标记，开局/菜单/编辑清空。实际吃帅终局仍保留最后着法。

手数为有效提交总数，开局000，至少三位，超过999完整显示。非法/选子/确认不增加；悔棋恢复；终局保留最终手数。数字及红方步时不影响手数或胜负。

## 悔棋和过期任务

一次撤回上次玩家行动：红走黑未走时撤一步，双方走完撤两步。次数不限，可继续撤至初局；没有可撤步则提示尚无棋步可悔。结果页不开放悔棋。

有可撤步时点击悔棋先显示“要悔棋嗎？”及“是/否”，默认聚焦“否”。确认前不消耗历史、不取消AI任务；屏蔽棋盘与其他对局按钮。点“是”关闭弹窗并执行撤回，丢弃期间已就绪的回棋；点“否”只关闭弹窗，已就绪的AI回棋立即提交一次。与认输确认相同，弹窗期间计算、附加等待与当前方计时继续。

恢复玩家落子前的棋盘、手数与上次AI数字和落子边框，清空选择/临时提示，新红方步时清零。计算/等待均可取消，不恢复成累计时间。

每次开局、悔棋、认输、回菜单递增局面版本。计算与等待绑定版本、规则档案、行棋方；提交前复核，过期即丢弃。搜索使用私有工作棋盘，试走不进入可见局面、手数或步时历史。

## 动态等待接口

计算输出合法着法、完整深度、根候选数、战术摘要和可用分差；表现层计算一次W并锁定截止点。困难/自定义同一策略，快速W=0；等待期间不额外搜索。

候选分差只能使用同一完整深度的可比较精确值，截断上下界不能冒充次佳分。书库命中时用已有特征降级计算复杂度，不为制造等待再做完整搜索。公式、归一化与试验初值见[AI方案](ai-design.md)。

## 声音设置补充（2026-10-24）

标题/模式菜单画布右下「設定」进入`audio-settings`，返回保留模式焦点。标题与棋盘使用同一个`music-select`，按全部/探索/战斗/任务/其他分类，每页5首，可返回、上一页、下一页、选曲或无BGM。推荐曲排在各分类可见曲目前并标记。选曲后回设置；保存全场景共用的一首曲目。音量默认100%，±10%限制0–100%；0%保留曲目。普通落子50882/将军50888共用音效开关，默认开，可独立关。设置仅本次脚本生命周期有效。

标题和棋盘画布内均有设置入口，保留右侧原三个对局按钮，新增设置位于它们下方。声音设置采用三行等距布局：背景音乐/音量/走棋音效行中心y=156/118/80，标签左边缘x=32，右侧控件区x=104..224，音乐与音效按钮等宽120，返回按钮居中。设置记录进入前的场景；设置/选曲期间不推进步时、AI搜索或待落子倒计时，返回恢复原场景及选子、棋盘、历史、AI任务和结果回看冻结状态，不重开对局。确认层/棋种层期间不能绕过弹层打开设置。已有对局回菜单仍需确认，并显示无法恢复提示。双方有效落子各触发一次音效：普通50882，将军50888，共用走棋音效开关。检测落子后的整盘攻击，包含发现将军/连续将军，一步只响一次；吃将终局不另报将军。沿用现有基本走法，只做反馈，允许送将和不应将。选子/非法目标/悔棋/重绘静音；关闭立即停止本脚本存活音效实例，再开启不补播。布局、信号、平台限制见[接入说明](audio-integration.md)，测试契约见[声音计划](../tests/audio-settings-plan.md)与[将军音计划](../tests/check-audio-plan.md)。
