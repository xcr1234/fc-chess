# 分帧 PVS 搜索内核（2026-10-23）

用户反馈中后期捉马时AI走闲。本轮按步骤2→5→6重构搜索，主要参考用户提供象棋小巫师0.6的SearchFull/SearchRoot算法组织。该压缩包SHA-256为f49a7ccb28adafe8c3ae71d46f08c1a979e8a48550e650dd0012867e92f25db0。源代码只读审阅；Lua为适配本项目独立实现，不是完整上游引擎翻译，未复制其位置表。检阅入口为XQWL06.CPP中的PVS试探、重搜、迭代加深和静态搜索。

## 本次实现

- game.ai保留AI.new/step/cancel及书库接口，拆出game.ai.search内核。根与内部节点共用显式栈，不再使用独立根候选分数列表。
- 深度大于1且已有首个候选时，对后续候选采用窄窗试探；分数超过alpha且低于beta时，以完整窗口重新搜索。试探返回时先撤销棋盘，再入栈重搜，重搜完成前不更新父节点最佳步。opts.pvs=false可在测试中使用普通Alpha-beta对照。
- 根节点完成才提交move/score/depth。预算、时间或用户取消可以发生于试探和重搜任一阶段；回退到上一完整轮，撤销棋盘、增量评分和将帅位置。
- 置换表只在完整节点写入；lower/upper只在可直接截断时复用，不额外缩窗，减少PVS边界状态混用。吃将分按ply归一化；确定吃将结果完成当前轮后可提前终止迭代。
- 默认总预算3200节点（原1600），主深度上限6（原3）。每帧16新节点/128操作、累计4秒截止保留；30FPS下可能先到时间截止。不是保证达到6层。静态吃子仍限制2层，己将危险时展开全部基本着法。
- 书库、增量位置/子力评估复用上一版；没有加入空步裁剪、复杂机动性评价或增量哈希。
- 困难/自定义共用的等待配置、预计秒数与追加等待接口沿用；等待不参与搜索预算。

## 验证与边界

- tests/lua-ai-pvs.lua：六个固定局面×标准/自定义，完整3层PVS与Alpha-beta分数一致；覆盖600次试探、10次重搜，并测试重搜中取消恢复。不是棋力排名。
- tests/lua-ai-threats.lua：六个拥挤局面的捉车/马/炮，以及四个稀疏中后期的车/炮/马/兵捉马局面；允许逃离、吃攻击子或拆掉炮架。不是实际用户棋谱复现。构造局面排除同时捉将及可用车将军反击等会使“必须立即躲子”预期不成立的条件。
- 六个拥挤局面旧版也通过：不能宣称这些证明修复用户原局。需要完整局面才能判定不躲马是失误、强制反击、合理弃子还是预算问题。
- ai-pvs-red.txt仅证明旧版缺少PVS内核特性，并非用户缺陷Red；原炮换马和既有战术回归继续保留。
- 对照宿主12样本：上一版11个2层/1个1层；新版3个3层、8个2层、1个1层。预算加倍且落子后局面不同，不能归因于PVS或声称同局面提速。固定3层小局面有重搜开销，PVS节点也可能更多。
- 总计算可能增加，Fengari单步长帧仍有波动；无真机性能结论，无对弈胜率数据。
