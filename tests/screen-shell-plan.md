# 全屏遮底与移动输入隔离（2026-10-24）

用户真机截图显示等比棋盘外露出3D场景和默认HUD，并要求禁用WASD移动。画面仍以256×224游戏画布为主体；本轮增加适配整窗的纯色遮底和输入屏障，不将外围扩展为新的玩法/美术区域。

| 契约 | 操作与预期 | 证据及边界 |
|---|---|---|
| 纯色铺满窗口 | 标题紫底、其他页面深蓝底，五画布四角不透明，不拉伸棋盘 | Lua模型4宽高组合、模拟器五画布×三页60个角像素 |
| 移动输入隔离 | 屏幕容器屏蔽按键穿透，W/S/A/D分别注册Down/Up并返回true | Lua模型检查8回调；模拟器15流程各输入8事件后状态保持。没有原神3D移动模型，仍需真机验证 |
| 点击隔离 | 全窗点击屏障在棋盘内容下方，边缘点击不进入棋盘；棋盘/弹窗仍可点击 | Lua模型检查层级/尺寸；五画布实际指针菜单/设置/选曲/走棋/确认回归 |
| 生命周期 | 窗口变化同步背景/屏障尺寸，内容等比居中；销毁移除整层 | Lua模型resize和destroy/reinit；同次产物模拟器启动/停止与页面回归 |
| 原生HUD | 使用当前职业引用的界面布局，关闭固有内容里可配置项的初始可见，保留客户端控件容器 | 官方《界面布局》《界面控件组管理》，由用户自行操作；Lua背景不等于已隐藏原生HUD |

Red：旧视图缺少全窗背景/输入层，4项均失败；Green见`npm run test:lua:screen`、`npm run test:screen:simulator`与records/screen-shell-*。回归复用原40场景/95断言与完整玩法用例，不以模拟器冒充原生HUD和角色移动验收。

新增接口依据：通过项目miliastra-knowledge-lua读取《客户端控件API文档》《容器节点控件》《客户端控件和客户端脚本》，核对`disableKeyEventPassthrough`、`disableCursorEventPassthrough`、`AddKeyEventListener`布尔返回和八种`KeyboardMove{Forward,Backward,Left,Right}Key{Down,Up}`枚举；布局/变换接口沿用已核对API。服务端知识库读取《界面布局》《界面控件组管理》确认默认HUD属于服务端界面配置，客户端Lua不能直接取得其控件索引进行调用。
