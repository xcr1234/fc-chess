# 平台完成通知：简单事件

Lua负责判断和去重；服务端只有3条无参数监听，各自设置固定结算状态，再设逃跑合法性为是，禁止结算关卡。

| 场景 | 通知预期 |
| --- | --- |
| 初次启动/中途离局/取消认输 | 无通知，不写平台状态 |
| 吃黑将 | FCChessWin一次，无参数 |
| 红帅被吃/确认认输 | FCChessLose一次，无参数 |
| 中性结束 | FCChessDraw一次，无参数 |
| 回看/悔棋/重开/返回标题/重绘 | 无新通知，保持已有平台状态 |
| 客户端重建 | 无初始化通知，不撤销旧结果 |
| 后续另一结果 | Lua选择新信号，直接更新最近结果 |
| 信号未定义 | 不崩溃、不逐帧重试，下一盘结果可再尝试 |

`npm run test:lua:completion`：7项，旧双参数/初始化通知Red→新无参数实现Green，禁止意外平台调用。`npm run test:completion:simulator`：PC/手机各10流程，核对实际生命周期信号接收、日志次数及后续继续操作，报告completion-simple-simulator.json。

接收探针没有值表示没有请求，不以默认false冒充初始化请求。原生玩家实体、节点接线、ESC及平台自身重连保留行为按docs/completion-integration.md真机验收。
