# 平台完成请求

用户明确选“下完一盘后允许正常退出”，禁止调用结算关卡。完成标记在本次游玩内保持，最近结果随下一盘结束更新；真实平台属性由服务端接线，模拟器只记录请求。

| 场景 | 请求预期 |
| --- | --- |
| 初次启动/开局/中途离局 | 初始化一次 Bool否、Int0，不解锁 |
| 吃黑将/红帅被吃 | Bool是，Int1/2，各一次 |
| 认输取消/确认 | 取消无请求，确认Bool是、Int2 |
| 中性结束 | Bool是、Int0，不冒报胜利 |
| 回看/悔棋/重开/返回标题 | 不清除已完成，不重复请求 |
| 后续另一结果 | 保持已完成，更新最近结果代码 |
| 信号未定义 | 不崩溃、不逐帧重试，新结果可再次发送 |
| 禁止强制结束 | Lua单测拒绝任何意外平台调用，模拟器结果后仍运行且可操作 |

`npm run test:lua:completion`：7项旧骨架Red→Green；用真实session吃将/输棋/认输行为，不从声音已消费的事件表取结果。

`npm run test:completion:simulator`：PC/手机各10流程，实际生命周期发送→接收探针变量/日志数量→继续运行。覆盖未结束离局、胜负、认输取消/确认、回看悔棋、重开/回菜单及连下更新结果。

服务端重连保护、玩家实体绑定及原生ESC标签需按docs/completion-integration.md在真实编辑器接线和验收；不把探针里的Bool/Int当成原生属性已经设置。
