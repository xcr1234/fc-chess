## 规则、动作与真值

| ID / 要求 | 前置与动作 | 独立预期 / 边界 | 运行层 |
|---|---|---|---|
| RULE-GEOMETRY | 手工摆放炮架、马腿、象眼、河界、九宫和边缘棋子；生成指定着并查询目标攻击 | 指定允许/禁止表；同时覆盖普通/自定义及双方，不从待测生成器复制真值 | Lua |
| RULE-CUSTOM | 红士出宫、红相过河/塞眼，黑士相保持范围；全部改车和恢复阵容 | 生成、攻击、搜索与规则档一致；自定义禁库，材料评价非零且低于胜负分 | Lua / simulator |
| RULE-CAPTURE | 己将受攻击但能先吃敌将、飞将、被牵制棋子先吃将 | 立即胜利优先；普通攻击者的自将不阻止实际吃将；将帅照面本身不结算 | Lua / simulator |
| RULE-FORCED-LOSS | 没有安全着但有基本着；搜索/零预算保底后实际提交 | 返回基本合法着，不预先判败；对手实际吃将后才结束 | Lua |
| RULE-NO-MOVE | 完整九宫被本方士堵住，仍有双将；分别让一方/双方无基本着 | 单方跳过不增加手数；双方无法继续不记胜负和，不依赖删掉双将伪造空列表 | Lua / simulator |
| RULE-REPEAT | 双方马往返，分别使用生产档和离线标准档；随后撤销 | 生产重复无裁判结果，标准评分隔离；撤销回到相同行棋方、哈希、评价和历史 | Lua |
| STATE-RESTORE | 吃子、移动将帅、空步/真实跳过、预算/时钟中断及完成后反复调用 | 原棋盘不可变，工作棋盘/双将/行棋方/评价/哈希/历史完整恢复；完成后调用无二次推进 | Lua |
| CACHE-ISOLATION | TT 命中后改变规则、行棋方、校验签名、深度/静态/延伸/路径语义 | 不串规则或路径精确值；正负胜负距离可逆，重复读取不漂移 | Lua |
| SESSION-POLICY | 同局面/seed 经真实会话进入困难与快速，等待中检查任务；切页/悔棋 | 同搜索结果，只有附加等待不同；等待不继续搜索，取消结果不落入新局 | Lua / simulator |
| THREAT-ORACLE | 四个拥挤局面、六个无保护重子受兵攻击、两组马炮双攻、四个稀疏捉马局面 | 单目标需处理；双攻允许救马或救炮/反击，不强制每个目标都跑；所有用例均执行并汇总失败 | Lua / pinned JS |

真值来源为 `docs/game-spec.md` 的游戏契约、明确的手工几何预期及项目内固定 JS 1.0；JS 标准安全规则不作为生产吃将裁判。手工局面是构造测试，不冒充用户实战棋谱。

## 执行与证据

- 先补用例与静态检查，再在现有可运行内核执行。行为已满足时记录补充回归通过，不人为破坏代码制造 Red。
- 如发现生产缺陷，保留最小失败局面/断言，再做必要修复与定向、相关全量回归。
- 原生用例独立夹具、显式 `dt`、真实生产引擎，无受控回棋代替搜索；先核对 FixtureReady，再检查可见结果和状态恢复。
- 使用同次打包产物显式同步正式/测试存档，报告带 SHA-256。原有 `records/lua-step5-regression.json` 修改不覆盖。
- 本次不运行 400 局棋力赛或真机测试；这些仍是新引擎独立验收缺项。模拟器规则通过只能证明本批规则与接入行为。

新增原生用例：`ai-counter-capture-priority`、`ai-custom-advisor-defence`、`ai-custom-elephant-defence`、`ai-no-basic-move-skip`、`ai-custom-standard-army-search`、`ai-custom-fifteen-rooks-search`。自定义搜索/防守夹具仅将完成后的附加等待设为 0，不注入搜索结果或减少真实搜索预算。

独立命令：`npm run test:ai:rules`；完整串行回归：`npm run test:ai:regression`，包含固定 JS 1.0 核心对照，单个套件失败仍继续其余套件。报告记录源码清单、测试哈希和同次产物哈希。
