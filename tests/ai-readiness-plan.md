# 新 AI 运行测试与棋力初测

日期：2026-10-24。被测源码为当前提交 `5c19390` 的 JS 1.0 新内核，复用已同步的产物。当前在步骤 6；本轮不修改算法或产品预算。

## 顺序与口径

1. 串行运行宿主性能采样、不并发其他测试：标准、15 车、自由士相，黑方实际出库局面；1/2/4/8 秒逻辑预算，30/60 FPS，重复两次。记录初始化、step P95/最大、实际宿主计算时间、完成深度、节点与截止原因。无墙钟帧等待，逻辑秒数不是实际 CPU 时长，也不是设备性能。
2. 三类阵容分别用真实新引擎对双方最多连续走 80 个半回合，检查基本合法性、工作棋盘/行棋方/评价/哈希/历史恢复、终局与无着跳过；记录棋谱和重复，不把生产重复判和。步数上限记未决，不伪造完整对局通过。
3. 标准规则棋力初测：从固定 JS 随机合法线路取 8 个不同静态分近似均衡的快照起点，交换红黑 16 局，每手请求 100ms、最多 100 半回合。双方禁库、根随机关闭、每次搜索空缓存/根前历史，裁判统一为无安全着负、第三次重复和、手数上限未决。保留实际时长和协作式截止超时，不称严格硬实时公平赛。起点来自同一条线路，彼此相关，也未以深搜排除强制杀；它们不构成独立封存棋力集，成对重采样区间只描述本次集合。

JS 对手是项目内固定 JS 1.0 原样搜索，唯一改造为搜索入口检查截止并保留上一完整根迭代；不修正其已知 TT 分数漂移。Lua 使用离线标准档，只改变测试资源预算。该对照只验证标准档的短时限行为，不是生产吃将档对局。

## 退出与缺项

- 状态恢复/合法性失败应留最小棋谱，回步骤 5 修复；性能不满足时如实报告，不通过增加逻辑等待掩盖。
- 短时限、少量起点及宿主解释器速度差异不能直接证明或否定正式预算下接近小巫师。报告 W/L/D/U、成对统计区间及实际超时，避免只列已结束棋局胜率。
- 正式 120 局面（40 封存）、标准/吃将各 400 局、生产吃将 JS 适配对手、设备端完整对局与性能仍按原方案独立验收。本轮不把这些缺项写成完成。

命令：`npm run test:ai:runtime` 检查测试驱动本身；`npm run test:ai:readiness` 先串行采样再做持续对局；`npm run test:ai:smoke` 做标准规则初测。结果分别为 `records/ai-readiness-performance.json`、`records/ai-readiness-soak.json`、`records/ai-strength-smoke.json`。

## 已执行结果

本批 48 个性能样本、3 盘 151 半回合持续对局及 16 局标准档初测已执行，见 [结果分析](../docs/ai-readiness-results.md)。状态检查通过，但性能/棋力目标不能据此标为通过；15 车首轮与长 step 是下一轮优先排查项。基准驱动 6 项检查及原构建工具合计 28/28 通过。
